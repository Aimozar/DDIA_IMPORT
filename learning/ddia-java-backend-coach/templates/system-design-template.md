# 系统设计分析模板

## 1. 业务场景

系统要解决什么问题？核心用户行为是什么？

## 2. 核心数据模型

主要实体：用户、订单、商品、库存、支付单、消息、日志。

## 3. 存储选择

| 数据类型 | 存储系统 | 原因 |
|---|---|---|
| 核心交易数据 | MySQL / PostgreSQL | 强一致、事务 |
| 缓存数据 | Redis | 低延迟 |
| 搜索数据 | Elasticsearch | 全文检索 |
| 事件日志 | Kafka / RocketMQ | 异步、削峰 |
| 分析数据 | ClickHouse / Hive | OLAP |

## 4. 索引设计

说明主要查询路径和对应索引。

## 5. 缓存策略

- 缓存什么？
- 缓存失效策略？
- 如何防止缓存穿透、击穿、雪崩？
- 缓存和数据库如何保持一致？

## 6. 复制与分区

- 是否需要主从复制？
- 是否需要读写分离？
- 是否需要分库分表？
- 分区键是什么？
- 热点数据如何处理？

## 7. 事务边界

哪些操作必须在同一个本地事务中？哪些操作不能放进本地事务，需要异步或补偿？

## 8. 一致性要求

| 场景 | 一致性要求 | 方案 |
|---|---|---|
| 扣库存 | 强一致 / 最终一致 | 事务 / 预扣 / MQ |
| 支付回调 | 幂等 + 最终一致 | 唯一键 / 状态机 |
| 搜索索引 | 最终一致 | CDC / MQ |
| 缓存 | 最终一致 | 删除缓存 / 延迟双删 |

## 9. 故障处理

- 接口超时怎么办？
- MQ 重复消费怎么办？
- 下游服务挂了怎么办？
- 主库挂了怎么办？
- 消息积压怎么办？

## 10. 可观测性

日志、指标、Trace、告警、数据对账。

## 11. 风险点与取舍

说明系统中最重要的设计取舍。
